# Store assets

| Folder | Holds |
| --- | --- |
| `microsoft/listings.json`, `listings.md` | The Store listing text in all nine locales, and the claims it makes (see `listings.md`) |
| `manifest.json` | Every Store screenshot in listing order: its raw source, theme, en-US caption and alt text (LIST-8); `{locale}` in a path stands for each listing locale |
| `raw/microsoft/<locale>/` | The raw captures, one folder per listing locale: the test VM's whole desktop at 200% display scale, each with the `.json` sidecar the capture helper writes |
| `microsoft/screenshots/<locale>/` | The listing screenshots, rendered from that locale's raw captures, with the generated first screenshot (`00-hero-dark.png`); the README shows the en-US ones (ASSET-10) |
| `microsoft/text-free/` | The hero's one text-free copy, drawn from the en-US capture, for a web page |
| `capture/` | The capture scripts and the synthetic text each language shows (`sample-data.json`) |

## Screenshots

Captured from the real installed app with synthetic settings, never from a personal machine (LIST-8). Every listing language has its own set, fully localized: Windows itself, the app and the sample data (the typed phrase, and the app picked in the App or link shot) are all in that language (en-CA and fr-CA reuse en-US and fr-FR). Captures are taken on a 1920 x 1080 desktop at 200% display scale (3840 x 2160), which the renderer reduces to the Store size. The captions in `manifest.json` are the en-US `screenshotCaptions` in `listings.json`, in the same order and count; each other locale has its own translation there. The maintainer approves a new or changed set from the English screenshots and one sample language; the other languages must pass the automated checks.

1. **Capture** on the Windows 11 test VM with the windows-build-tools app-test helpers, one language at a time. Switch Windows to the language first (`app_test_language <locale>`, then a cold cycle, since it applies at sign-in), install a dev package and run `screenshot-desktop.ps1 -Mode Prepare -Scale 200` (dark mode, a 1920 x 1080 desktop at 200%, the dark wallpaper, window effects on). Then run `capture/capture.sh <locale>` from this repo's root: it runs `capture/capture.ps1` in the desktop session, which writes each shot's settings (dark theme, the app's language, the action, with the phrase and app from `capture/sample-data.json`), centers the window on the work area, finds every control by automation ID and saves the whole desktop with its `.json` sidecar (`Save-DesktopCapture`), then copies the captures into `raw/microsoft/<locale>/` under the manifest's names. `CAPTURE_PREPARE_LOCALE` can name a command that switches the language, so one `capture/capture.sh` run loops over every listing language. End the visit with `app_test_clean` and switch Windows back with `app_test_language en-US`.
2. **Render** with `npm run shots:render` (winui-app-kit's renderer; its README has the rules): each locale's captures are cropped to 1366 x 768 around the window in logical pixels and each 2 x 2 block averaged, with nothing composited or shaved, and written without an alpha channel to `microsoft/screenshots/<locale>/` (ASSET-9). It renders nothing while any listing locale lacks a capture. Every shot is in dark mode (LIST-8). Recaptioning needs no recapture; a new look does.
3. **Check** with `npm run check:screenshots` (part of `npm run validate`): every listing locale has every capture, each with its sidecar, taken dark, at 100% or 200% scale, with effects on and the dark wallpaper; the window in each screenshot is dark and fits its crop; every screenshot was written by the renderer at exactly 1366 x 768 as 8-bit RGB without alpha, with a caption and alt text; the captions match the en-US `screenshotCaptions`; no stray file is present in a locale folder; and the count is 1 to 10.
4. **Sync** with the next Store release: the Store workflow's `screenshots` input uploads every locale's set, its hero first, with that locale's captions from `listings.json`, and keeps the listing's logos. Check the draft in Partner Center before submitting it.

A UI change that shows in a screenshot means recapturing that shot; the release skill's checklist says when.

## The first screenshot: a generated hero

Store search shows only the first screenshot, at about 320 x 180, so it is a generated hero (D-123): the split layout, a purple brand panel with the icon, name, headline and subline on the left, beside the real UI enlarged from that locale's `raw/microsoft/<locale>/04-windows-function-dark.png` on the right: the Copilot key action page with Windows function chosen, where people pick what the key does. Each listing locale has its own, drawn from its `heroHeadline` and `heroSubline` in `listings.json`; en-CA and fr-CA use en-US's and fr-FR's. Its caption is the subline. `npm run hero` draws them (devkit, through winui-app-kit's `scripts/devkit`), and `npm run check:hero` in `validate` fails when one no longer matches its inputs or a listing locale has no capture. The text-free copy is drawn from the en-US capture. New or changed headlines are approved by the maintainer, like any screenshot.
